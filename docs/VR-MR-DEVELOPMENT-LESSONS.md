# VR / MR 开发复盘与防复发规则

更新：2026-11-01。适用于本项目的新游戏、重大改版与交付。阅读顺序：本文 → [质量检查表](VR-MR-QUALITY-CHECKLIST.md) → 当前游戏的设计与版本证据。本文归纳已经发生的问题，不把候选修复、模拟器结果或用户口头反馈改写成全版本、全设备保证。

本轮实际应用见[四款大改对应整改表](../releases/four-game-upgrade-20261101/LESSONS-APPLICATION.md)。新项目需要建立同类表，逐项关联实现与回归证据，不能只写“已阅读”。

## 事实和证据怎么记录

- **已确认**：有实际代码、失败/修复回归或明确操作记录支撑的局部结论。
- **用户报告**：保留用户看到的现象及设备，不假定安装包哈希已核对。
- **待验证/假设**：不能借用旧版通过、测试夹具通过或同类问题的原因来宣称解决。
- 本地逻辑、编译、程序回调/ECS、原生系统输入、光学手势、首次玩家体验是不同证据层。每个结果写清版本、输入来源和限制。

## A. 玩法、空间与手势

### L01 关卡多不等于玩法多

**发生过什么：**《深夜食堂》初版八关都是放三样食材再搅拌；《房间守望队》初版只有单个不进攻目标；《方块室友》的内容深度也受到质疑。菜单、关卡数字和测试数量掩盖不了重复。

**已做/尚欠：**食堂 v2 已引入炒、双面烤、分批煮、焖蒸、卷制和冷热双单；守望队 v2 已有多敌、核心受击、敌弹、波次、护盾和首领；室友 v2 有六类活动。这些是现有基础，并非新一轮升级的新增内容，也尚非首次玩家质量验收。本轮要进一步增加可理解的选择、组合和可见成果。

**防复发：**设计每一关时写出“新增判断/操作、与前关的区别、失败原因、恢复办法”。高难度主要增加决策组合，而非缩小命中区、加长等待或单纯堆血量。至少保留一条宽容的新手路径。游戏时长由实际试玩计时，不能由关数推算。来源：[四款候选说明](../releases/four-game-overhaul-20261031/README.md)。

### L02 空间初始位置必须正确，重新居中只是补救

**发生过什么：**用户报告魔术桌和面板整体偏左约45度，后续候选桌面又有约30度偏航；还有面板缺失。用户不应先后退、扭头或寻找重新居中，才能读懂游戏。

**修复与证据：**桌面、道具、面板和交互坐标统一到同一个稳定的新鲜头部朝向；实际解锁状态下自动校准曾取得34/37ms头姿，看到正前方桌与双面板。锁屏时约2Hz、消费时已过期的头姿未通过250ms门限，不能使用陈旧数据伪装成功。面板挂载/资源就绪需单独检查。来源：[原生续测记录](../releases/four-game-overhaul-20261031/NATIVE-CONTINUATION-20261031-EVENING.md)。

**防复发：**启动先取得可信姿态再放置；不能把世界原点当玩家前方，不能仅旋转模型却不旋转面板/碰撞/射线坐标。测试0/±30/±90度开局、坐姿、站姿、延迟追踪与暂停恢复。靠身体一侧的桌边留约20cm间隙；这是设计/估算，不冒充真实躯干追踪。自动开局实操与固定测试姿态夹具分别记录。

### L03 窗口变大时，内容和命中区必须一起变大

**发生过什么：**修复所主操作区小而远，侧窗底部功能不明显、被裁切、滚动不顺畅。

**修复：**按实际安全三维范围统一缩放工作台所有可见与碰撞后代，保留每侧6mm余量；放大面板与首屏提示，滚动内容保留可达路径。系统管理的 DefaultWindowContainer 初始距离不能用放大内容冒充“自动拉近一半”。详细高频输入日志会增加负担，关闭后用户报告滚动更顺畅。

**防复发：**默认/最小/最大尺寸都检查文字、模型、碰撞和底部按钮；优先把核心动作放在首屏，补充可滚动提示。系统窗口边角的缩放把手不是游戏手柄依赖。来源：[修复所最终状态](../releases/repair-workshop-latest/FINAL-STATUS.md)、[根规则](../AGENTS.md)。

### L04 手势优先不等于给物体自由六轴运动

**发生过什么：**星台铜镜在真机上难以移动和转角；最终星钥一捏就横倒，难插入插槽。模拟器鼠标抓取成功不等于光学手势可用。

**修复：**铜镜固定中心，只调整两个所需角度，增加点按微调、方向反馈和说明，正常松手保留角度。星钥保持竖直，仅跟随平移；正常松手距离槽口6cm内才吸附，持有时靠近不自动完成，保留抬起、碰撞、所有权和取消校验。来源：[铜镜候选](../releases/lost-star-observatory-0.3.1-hand-mirror-rc1-20261027/README.md)、[根规则中星钥反馈](../AGENTS.md)。

**防复发：**为每件物体明确必需自由度、旋转中心、边界、抓取者、松手/取消区别、容错吸附和可达替代路径。机关只需要转轴就不要让玩家搬动六轴物体。不要靠临时锁死全部交互来回避问题。

### L05 启动时的闭合手不能自动拿起道具

**发生过什么：**魔术一进入右手就与杯子绑定，未主动抓取却拖动杯子。

**修复与边界：**每只手先观察到张开，随后新的捏合边缘才允许近手抓取；单一所有者，正确区分直接手、系统射线和取消。用户杯球慢拖已确认跟随与完成，其他四套正式实操仍不因此自动算通过。

**防复发：**覆盖进场已捏住、追踪恢复仍捏住、双手争抢、失去追踪、背景切换、射线/直接抓混用。程序必须等待明确意图；不要以任何手位置变化替代抓取开始。来源：[原生续测记录](../releases/four-game-overhaul-20261031/NATIVE-CONTINUATION-20261031-EVENING.md)。

### L06 指向、选中、操作必须可区分

**发生过什么：**修复所用户觉得眼动选择疲劳、不准；重复选中若同时旋转容易误操作。

**修复：**选择水路只选择，不隐含旋转；使用明确的90度按钮、转动动画、轻音效。用户确认 Swan OS6.2路径：设置 → 眼与手 → 交互方式，可在眼手交互里开启快捷切换手势射线，或切到手势射线。首屏给出提示；这是系统能力，不是游戏自行绘制的假手部射线。

**防复发：**新手完整路径支持系统点按；焦点高亮、选中状态、动作结果不混用。只在确有需要时增加自定义交互；不因需要手部数据擅自更改窗口/全空间架构。来源：[修复所最终状态](../releases/repair-workshop-latest/FINAL-STATUS.md)、[根规则](../AGENTS.md)。

### L07 任务名词必须指向用户看得到的对象

**发生过什么：**星台“把月光反射到星纹”没有解释星纹是什么，实际目标是面前偏低的蓝色月球状球体；铜镜也缺少操作说明。修复所转视角按钮藏在下方，用户未必知道。

**修复：**使用具体颜色、形状、相对位置描述目标，动作提示写清“选哪个—怎么做—成功时看到什么”；隐藏功能在首屏给入口/提示。

**防复发：**每个首次机制至少有目标、动作、反馈、失败恢复四项。图形/颜色/文字配合，不只靠颜色或设定名词。由不看设计文档的人验证第一分钟。星台单次用户通关10多分钟符合10–20分钟目标，但不代表新手群体时长。来源：[根规则中真机反馈](../AGENTS.md)。

### L08 MR 必须使用真实环境，扫描失败也要可解释

**发生过什么：**室友面对墙壁仍无可靠表面；候选排序变动可能导致确认时换到另一个平面；切换摆放模式可能绕过追踪就绪。

**修复：**持续采样新鲜头姿，保留350ms门限；按候选身份保存选择，方向提示跟随该候选，重新扫描清计数，模式变更不能绕过就绪。真实模拟器平面扫描38个/3个可用的证据仅证明该模拟器场景，不能保证Swan任意墙桌都可用。

**防复发：**明确展示未通过原因（追踪、平面朝向/大小、内容覆盖等）；确认前预览；真实与虚拟练习显式分开，不造假平面冒充扫描成功。覆盖候选重排/消失、窄桌、墙角、斜面、丢追踪和恢复。不要把世界固定内容加透视背景称为已经利用房间语义。来源：[后台修复记录](../releases/four-game-overhaul-20261031/BACKGROUND-PREP-20261101.md)、[根规则](../AGENTS.md)。

## B. 模拟、声音、资源与存档

### L09 命中结果必须发生在弹丸抵达后

**发生过什么：**守望队刚捏合敌人就消失，弹丸尚未飞到。

**修复：**创建真实飞行的游戏投射物，按运动段寻找最近交点，到达后处理敌人、护盾、友方、场景及敌弹；低帧率用扫掠碰撞，不能用点击时立即扣血再补播动画。

**防复发：**测近/远目标、遮挡物在前、多碰撞体排序、帧间穿透、暂停恢复、同目标多弹、朋友与护盾。敌人攻击有可读预警、核心受伤与失败恢复，不只让敌人排队等点击。来源：[四款候选报告](../releases/four-game-overhaul-20261031/TEST-REPORT.md)。

### L10 声音不只是“调用了播放函数”

**发生过什么：**引力弹弓用户报告尖锐鸣叫；守望队缺BGM/分类命中音；室友重复进度提示；密集SoundPool音效可能挤掉音乐。

**修复与不确定项：**引力弹弓已有低响度/音色调整，缺受控录音不能断言鸣叫唯一根因。守望队分配音效/音乐优先级，关闭音效和退后台明确停掉旧音效；室友用状态变化单一入口播放一次，恢复/换关不补播。后台逻辑通过不代表实际听感已验收。

**防复发：**音乐与音效分别低音量、可关闭、设置保存；连射、重试、切后台和恢复不叠音/补播。命中对象有可辨区别，避免尖锐循环。检查素材授权、循环接缝、实际扬声器/头显听感；无声模拟器不能签听音通过。来源：[后台修复记录](../releases/four-game-overhaul-20261031/BACKGROUND-PREP-20261101.md)、[引力弹弓说明](../Projects/Claude/GravitySling/README.md)。

### L11 缓存的引擎资源必须有明确寿命

**发生过什么：**守望队使用已关闭的缓存材质导致崩溃；共享模型、音频、材质可能被局部生命周期释放。

**修复：**把共享资源提升到正确的长寿命拥有者，释放次序和实体使用周期一致。不要把“进程还活着”当成所有资源已显示。

**防复发：**反复换关、退出重进、加载失败重试、后台恢复时检查模型和材质；共享资源只释放一次，销毁后引用不得进入新场景。高频循环避免反复分配材质/实体，动画和日志有预算。来源：[四款候选报告](../releases/four-game-overhaul-20261031/TEST-REPORT.md)。

### L12 后台迟到输入和恢复过程不得改写游戏状态

**发生过什么：**食堂退后台后迟到的放料、调火、重开与口味回调仍改变订单；园林初始化时可能先写空园再读旧存档。

**修复：**食堂集中前台/资源/暂停门禁，新六例中旧代码四例失败，修复后通过；园林启动先加载已保存状态，五组Android存档回归通过。魔术完成只保存一次、取消不保存、重玩保留解锁有专门测试。

**防复发：**恢复优先于首次默认写入；保存需版本化、校验和安全默认值，新增内容不能清旧进度。前后台、暂停、对话框对计时和输入采用明确一致语义。测试迟到回调、重复完成、部分/损坏存档、新字段缺失、旧版升级。来源：[后台修复记录](../releases/four-game-overhaul-20261031/BACKGROUND-PREP-20261101.md)、[园林存档说明](../Projects/Claude/PalmGarden/README.md)。

## C. 测试、交付与协作

### L13 相似启动现象不等于相同根因

修复所/星台存在模拟器SDK原生初始化慢或ANR记录。星台特定事件的主线程落在 System.loadLibrary → libhoudini → linker64，另一个事件还有安装/启动重叠干扰；这支持PICO进一步调查，不证明所有未来超时都属PICO。魔术后来实际存在追踪新鲜度不足，必须单独排查。

**防复发：**记录包/版本/PID/退出原因/完整栈、资源就绪、姿态时间和是否锁屏/并发安装，先区分进程启动、SDK初始化、场景加载、可交互。不能为“通过”改ABI、任意异步初始化、接受陈旧姿态或隐藏超时。真机不复现也需要实际证据。来源：[精确启动事件报告](../releases/lost-star-observatory-0.3.0-fullvr-tested-20261026/startup-diagnostics/STARTUP-DIAGNOSIS.md)。

### L14 自动化输入失败要先判断输入有没有到达

发生过管理员模拟器与普通工具权限不一致、自动慢拖实际约0.08秒即松开、别的任务打开应用抢占、主界面仍在却提示用户开始操作。还曾把模拟器“轨道旋转”当原地转头，造成约1.69m位置移动和侧视面板。

**防复发：**先确认当前原生画面、焦点、权限、实体高亮和输入回调；自动拖两次无有效回调就停止反复尝试，说明限制并安排一次简短人工对照。必须先让用户确认游戏可见再开记录；等待人工时不设会退出游戏的短倒计时。原地转头用经过验证的位置不变控制；每次取新窗口坐标。锁屏不能绕过，黑图不能修成验收图。来源：[原生续测记录](../releases/four-game-overhaul-20261031/NATIVE-CONTINUATION-20261031-EVENING.md)。

### L15 屏幕使用是独立且可撤回的授权

发生过预计几十分钟实际长时间占屏、用户接管仍有蓝光指针残留。CLI、隐藏窗口参数、普通androidTest也可能启动Activity/抢焦点，不能据此声称后台。

**防复发：**测试前列具体动作和时间，优先离线；到时/用户接管立即停输入，留收尾预算。没有新授权不重启设备、操纵窗口或播放声音。真正无UI测试必须已验证没有Activity/输入/音频副作用。结束释放鼠标键、恢复数据、关闭测试AVD并释放控制会话；标记残留只处理已确认的辅助组件，不能杀掉用户浏览器。用户后来确认辅助组件退出后指针消失。来源：[根规则](../AGENTS.md)。

### L16 原生、夹具和真机证据不能互相冒充

加速时间、直接生产回调、固定姿态/未解锁存档夹具可以验证规则/ECS，但不能代替自然速度的完整实操。JVM数量不能证明视觉、光学手势、舒适度、趣味或商店星级。旧版通过只可沿用明确未改变的路径。

**防复发：**每份报告写APK哈希、版本、原始证据、测试输入、范围和失败/未测项；保留失败记录，不用新成功覆盖旧失败。自然通关与测试入口通关分列；四款均离线，没有业务服务器，不虚构“服务器验收”。用户负责的真机任务不无限重开；新变更才重测受影响内容。来源：[后台检查范围](../releases/four-game-overhaul-20261031/BACKGROUND-PREP-20261101.md)。

### L17 存档、用户备份和旧包必须可恢复

发生过整目录归档误移动用户的 repair-workshop_final1.apk；测试清理中途超时；ADB大文件管道传输截断；旧脚本固定旧版号可能回装错误版本。

**防复发：**发布只更新自己拥有的命名文件，不动用户额外备份。每次设备会话新备份当时状态，不拿旧快照覆盖后来的进度；逐文件回读校验文件集、字节数和SHA256，安装包也回读；恢复后不再启动游戏造成新写入。传输无PTY且验证完整。部分清理失败明确报告，不写“已全部恢复”。来源：[根规则](../AGENTS.md)、[续测恢复记录](../releases/four-game-overhaul-20261031/NATIVE-CONTINUATION-20261031-EVENING.md)。

### L18 交付源码、仓库权限和商店状态必须实际核对

引力弹弓曾出现工程拷贝不完整、有APK但缺引用的源码/测试。微缩奇案审核仅提供 GitHub 下载 timeout 一行：本地认证下载成功、提交和部署公钥匹配，仍不能代替PICO服务器链路。私有仓库表单还需完成“已添加公钥”确认。用户重提后报告两款审核中，不等于已发布。
